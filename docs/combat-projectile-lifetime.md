# 远程射弹独立视觉寿命

锁定原 Unity CardLoop `a11a89b04cea8370476f2559b639bb9b4cbc08d8`。

## 源行为

`CombatManager.SpawnProjectile` 把射弹实例挂在 `WorldCanvas`，不是战斗框或攻击者卡牌上。
`CombatProjectile.Fire` 在创建时确定世界起点、终点，启动线性、独立于 timeScale 的 tween，
其完成回调仅销毁自身。`CombatTask.CleanUpForMerge` 停止旧攻击协程和关闭旧框，
没有取消该独立射弹。因此旧协程不会在视觉抵达后继续结算伤害，而视觉仍走向原终点。
Main 和 Island 的箭与魔法射弹序列化时长为 0.5 秒；C# 字段默认 0.6 秒不替代作者参数。

## 本次迁移范围

- 对已经捕获世界端点的远程/魔法 travel 建立独立视觉计时记录。
- Board 先推进旧记录，再执行当帧模型事件；新的 capture 从零开始，不追补发射前的时间。
- 目标移动、旧任务合并或删除、卡牌视图移除均不重定向或立即销毁该视觉。
- 原时长完成时精确写回原终点并释放节点，且不会修改模型、触发命中或消耗随机数。
- 同时保留旧任务射弹与新任务射弹；同任务再次发射时也独立保留前个尚未完成的实例。
- 重复 sync 不重建节点；完成标记阻止旧快照复活。
- 带 visual_motion 的恢复记录从剩余时间初始化一次；下一次真实 capture 解除完成标记。
- 世界/场景 reset 仍显式销毁所有暂态视觉与计时记录。

无实际端点的旧存档继续旧 phase 驱动兼容路径，不伪称恢复了原本不可得的世界端点。
本次不更改攻击计时或伤害规则，不启用 active resize，也不推断近战 KillTweens 后的协程调度帧。
非终结 RemoveCombatant/Flee 是否停止协程是已有模型合同差异，不借视觉修正改变其规则。
独立视觉不序列化脱离任务的在途对象；与原存档恢复策略一致性仍待专项验收。

## 验证

`test_combat_projectile_lifetime.gd` 覆盖独立飞行、固定端点、清理、重复同步、恢复、
同任务下一次发射及实际模型 merge。模型用与原场景同样的 0.5 秒配置，
确认旧任务取消后无迟到伤害和 RNG 消耗。测试还用人工 0.6 秒夹具检查计时逻辑不硬编码作者时长。

这是 Godot 原生无头对象/行为回归，不是 Unity 运行时逐帧对照、GPU 或同场景截图验收。
