# Title save-management controls

The native title now exposes Archive selected and Archive all listed slots. These are deliberately recoverable counterparts to the source Delete/Clear controls, not permanent deletion. A scroll container keeps the additional controls reachable without claiming original title-layout parity.

Each request calls prepare_delete_slots, then shows the exact sorted slot IDs and count. The confirmation includes primary saves, backups and temporary artifacts, including recognized invalid/temp-only slots. It explicitly excludes Options, legacy saves and existing archives. Archive all means the IDs in the prepared listing; a slot arriving later is not silently included. No file changes occur before confirmation.

Confirmation consumes its prepared plan once, including on failure. The helper rechecks the current artifact set and hashes. Stale or changed files fail without moves and require a fresh plan; the UI never silently retries. Cancellation clears the plan. Entering gameplay or returning to title invalidates any interrupted confirmation. Archive operations are restricted to the title, so they cannot discard a running live session. If a move/rollback fails, the UI reports the helper's retained recovery archive and incomplete-rollback count instead of claiming success.

Archive inventory lists recognized saved entries, scene/day, and backup-recovery status. Invalid entries remain visible as diagnostic rows with Restore disabled. Restore copy into a new slot revalidates the chosen archive and allocates the lowest currently unoccupied slot. It preserves archive bytes, selects the newly created copy and stays at title. It does not load or mutate the current campaign; Continue is a separate explicit action. Repeating Restore intentionally creates another copy. A changed/invalid archive or failed allocation reports failure without silently replacing a game.

Unknown files, legacy files, Options and old archives remain untouched. There is no archive purge control. Restore-copy and recoverable deletion are native safety additions, not Unity-save compatibility or exact source destructive behavior. Single-writer assumptions, links, transactional preflight and rollback limitations are documented in save-slots.md.

`test_slot_management_ui.gd` uses only unique test-owned local paths and real imported gameplay metadata. It covers empty controls, live-game restrictions, exact confirmation scope, cancellation/repeat confirmation, stale hashes, selected/all-listed archive, post-confirmation newly created slots, options/legacy/archive preservation, restore without load, repeated restore, changed archive rejection, invalid/temp-only inventory, interrupted confirmations and scroll accessibility. Headless structural tests do not prove native GUI sizing, pointer acceptance, Windows filesystem behavior or power-loss recovery.
