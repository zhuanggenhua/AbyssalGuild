# Day clock fill value precision

Source DayTimeUI assigns TimeManager.NormalizedTime directly to Image.fillAmount. TimeManager normalizes and Clamp01s; Image.fillAmount clamps again but has no hundredth-percentage snapping. Locked UIRoot timeProgress is the referenced sprite-backed Filled Image, Horizontal, origin Left. No null-sprite fallback or radial interpretation is assumed.

Godot4.7.2 ProgressBar constructs itself with step0.01. Range snaps a requested value to that step before clamping. With max_value1 this changes the real Board fraction0.12345 to0.12, an extra quantization absent from the original. This adapter configures step0 only for the locked source provenance and exact known sprite-backed filled-image configuration; unverified or unsupported configuration restores the ProgressBar's captured native step. It does not change the session clock or arithmetic producing the normalized fraction. Repeating the same setting produces no Range changed notification; sync and inputs are otherwise untouched.

## Rendering boundary, deliberately not solved
Godot ProgressBar still rounds ratio*(width−fill-style minimum width) to integer draw pixels, and draws no positive-width fill when that rounds to0. The source Image.GenerateFilledSprite instead returns immediately for fillAmount<0.001, otherwise computes a floating-point horizontal endpoint from drawing dimensions and sprite outerUV. At width300 with zero fill-style minimum,0.12345 gives native draw width37 rather than old snapped width36; original geometric extent would be37.035 before sprite padding/rasterization considerations. At0.00125, native rounding can still yield0 while source geometry is above its culling threshold. No pixel, sprite-padding, shader or subpixel parity is claimed by removing the earlier value quantization.

Original source ratio uses binary32; this patch does not purport to change the model's existing timer arithmetic to that implementation. It removes only an independently proven intermediary step. Tests assert live stored range value, not image pixels. Private actual Main/Island Board tests and the unchanged prior-stage negative show the same noncent fraction case.
