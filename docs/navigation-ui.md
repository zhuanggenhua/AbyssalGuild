# 标题退出与跨设备取消

`board.gd` 已接入独立的[取消输入适配](navigation-input.md)。来源仍是固定 StackCraft 版本的 `TitleScreen.Start`、`ModalWindow.Show`、`StackCraftInput.CancelWasPressedThisFrame`、`PauseMenu.Update` 和 `TimeManager.SetExternalPause`，只做静态行为核对。

## 已接入的行为

- 标题页明确提供 **Quit Game**。按钮只打开确认框；接受才退出，拒绝不退出。没有导入数据时该按钮仍可使用。
- 普通游戏中的 Escape 或手柄东侧按钮打开/关闭暂停菜单。选项关闭先返回暂停菜单，再次取消才恢复游戏。原有选中速度和手动暂停状态不变。
- feeding、selling、encounter、ready、game_over 期间不通过取消输入打开暂停菜单或选项。
- 标题退出、日终退出、存档归档、游戏结束返回标题和重置选项的原生确认框都能用 Escape 或手柄东侧按钮取消。可见确认框阻止下层菜单再次响应；取消重置不会顺便关闭选项。
- 重复退出请求不叠加确认框或绕过确认。确认授权只使用一次；已取消或在游戏状态变化后过期的确认不能触发退出。
- 现有窗口关闭规则不变：普通标题页直接退出；游戏进行中先保存检查点，失败则留在游戏；日终先提示不会自动保存该阶段，接受后保留此前检查点退出。未保存的选项仍须先成功保存。
- 退出分派有独立可注入回调和一次性保护。生产环境未注入时才调用引擎退出；测试始终注入计数回调，不会误关闭测试进程。

此次桌面改动没有改写持有牌堆的捕获/释放、商店解锁实时动画与输入例外、日终按钮布局或存档格式。
