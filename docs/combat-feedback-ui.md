# Combat event and pose adapter

The board reads individual target poses through `card_target_position` / `card_target_position_3d` for fighter geometry, equipment collision, nearest-friendly selection, chest withdrawal and dragged-tail origins. Model card.position remains a stack-root field. Before combat detaches a dragged tail, its source stack is temporarily translated to the drop point so the model's batch capture retains each member's source step. Remaining preceding members are restored immediately. Rendering and broadphase still use deterministic target poses rather than Unity's animated colliders; this is not physics-hit-order parity.

Combat timing belongs to the model. Normal board frames call Session.tick once. An external Options/Escape pause calls only combat.tick(0, real_delta), preserving in-flight travel/return while freezing day time, progress and death waits. No presentation await controls damage, loot or RNG. Attack audio starts at combat_attack_started. combat_hit uses the immutable ImpactFeedback descriptor: normal style hit, style hit then Critical, or Miss. Removed targets are safe.

A generated billboard shows damage (critical marked `!`) or MISS for one real-time second, at the source HitUI local offset with reflected Z. Its position is captured at impact, independent of later death/deletion. The separate CombatPresentation adapter now adds attack/return motion, projectile representation, hurt flash/rotation and camera offsets. See combat-presentation.md for source parameters and explicit easing/noise differences. Optional private hit sprite icons are connected; original font rasterization and GPU acceptance remain separate.

`test_combat_feedback_ui.gd` uses real imported gameplay definitions, private temporary save/options paths, and a silent recording audio adapter. It tests derived tail geometry, preceding-stack preservation, event ordering, menu-pause clocks, critical audio and popup lifetime/deletion safety. Muting is scoped to this geometry/event suite and is not a fix for runtime audio teardown. Existing audio tests remain unchanged.
