# CombatRect: source-backed board boundary
Unity source lock: StackCraft 1.0.0 / CardLoop `a11a89b04cea8370476f2559b639bb9b4cbc08d8`. The original combat rectangle is instantiated under the scene's WorldCanvas. Its stretched Visual child uses the default unmasked UI/Image Sliced, real single-sprite CombatRect, fill center, white tint and no raycast. Its local normal offset is +.025. Under Main and Island's effective +90° X WorldCanvas, that is world Y=-.025; it is not the previous translucent red quad at +.015.

The private visual importer resolves scene CombatManager's rectangle reference, its Image and sprite, and the effective canvas scaler. Regenerate the ignored private manifest with the normal licensed visual import; no source PNG or generated asset ships here. If the original visual cannot bind, there is no fake combat color replacement. Gameplay hit areas, size, placement and overlaps remain unchanged.

The mesh uses world-space UGUI 2.5.0 Image.GenerateSlicedSprite: source pixel border / ((sprite PPU / canvas reference PPU) × multiplier) and shrink opposing borders when the rect is too small. For the source, that is 64/(128/100×128) = .390625. A positive center quad with equal UVs on both sides remains a valid quad. The rendered node tracks center independently of mesh size changes. Local bottom-left sprite UV is converted once to top-left Godot texture UV. The original unatlased PNG reaches all four edges and its border consumes the entire source dimensions. This implementation supports that full extent contract; it does not infer trim/packing for other inputs.

Verification covers parsed source references, nine-slice geometry/UV and small rects, plus cached private source data and the live Board's resize, merge, position and lifetime. It does not establish native Unity DataUtility UV/padding, compressor results, Canvas transparent sorting on native graphics, or frame-by-frame pixel parity.
