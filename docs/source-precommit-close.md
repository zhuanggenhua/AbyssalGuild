# Source ordinary travel: pre-blackout window close

This bounded adapter covers an accepted original ordinary portal travel while its original playing scene still owns the outward fade. The locked source executes ingredient consumption before the departure save. Its application-quit callback saves the current old scene again outside the day-end lifecycle; load activation only occurs after the outward fade coroutine returns.

The native departure candidate is intentionally still separate. Saving the native live owner directly during fade would retain the completed portal and could retrigger travel after Continue. The adapter retains the original accepted traveler receipt and exact owner, stack/card object identities, craft generation, candidate and transition generation. Only that same pending outward transition, before blackout, may recapture a source-consumed old-scene snapshot through the existing source departure admission. At most one still-incomplete ordinary task is allowed; its current legitimate tail progress is retained. Mixed/completed work, changed owner/generation, unknown imports, menus, day-end and inbound transitions remain on the previous ignored-close path.

Successful save uses the existing checkpoint/timestamp/slot writer with a temporary save owner, resets that ownership immediately, and only then dispatches quit and cancels travel. The arrival candidate is never overwritten. Board cancel sites and tree exit clear the receipt; transition generation/callable identity prevents replay after external cancellation or another transition.

Failure policy is deliberately protective: snapshot validation or writer failure reports the specific error and leaves the current session/transition available for retry. This is not a claim that Unity's OS shutdown callback could veto termination. It retains the existing native save-failure safety policy while matching the source successful save contents and timing.

Focused private fixtures dispatch the actual Board WM_CLOSE_REQUEST notification and intercept the final quit callback, not an actual OS close. They cover normal close, legitimate incomplete same-frame tail, writer failure/retry, invalid snapshot/retry, source admission rejection, second portal, paused UI, stale generation and inbound fade. Fresh Continue verifies Main without consumed travelers or duplicate portal travel. Physical/native OS close ordering remains separate acceptance.
