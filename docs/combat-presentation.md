# Read-only combat presentation

Audited source: CombatTask.AttackSequenceCoroutine uses melee/None DOJump to the defender's transform +Y0.05, power1, one jump,0.3 seconds; return uses the current rectangle slot and the same power/duration. Ranged/Magic use CombatProjectile's linear, unscaled movement between +Y0.05 endpoints with the scene prefab duration. CardInstance.TakeDamage replaces the prior hurt tween: material flash0→1 after0.05 seconds,0.1-second legs with two yoyo loops; root Y rotation punch15 degrees over0.25 seconds with vibrato25. CameraController.Shake defaults to0.3 seconds/0.1 strength. HitUI punch scale is(0.15,0.15,0) for one real-time second.

CombatPresentation reconstructs travel/return from the model execution's saved positions, phase and remaining time, so Continue can restore the visual midway without replaying sound or resolving damage. Current layout positions supply the return destination. Missing tasks, merged tasks, cancelled attacks and scene/title reset remove projectile nodes. Death-wait returns to ordinary board poses. Models, saved card positions, clocks and gameplay RNG are never written by this helper.

Melee views jump; ranged actors stay home. Optional audited private projectile sprites are used when VisualAssets supplies them; otherwise a small generated colored marker denotes flight. Root-view hurt rotation carries labels and equipment with it. CardView's flash setter preserves independent selection emission. Camera shake uses h/v offsets, leaving navigation position and clamp state untouched. Gear attachment is synchronized after combat view offsets. The pick collider follows the view, while attachment/combat broadphase still uses target model poses.

DOTween 1.2.790 was identified from the locked dependency DLL without execution. Jump now uses its nested OutQuad mapping; rotation and popup punches use its weighted segments and additive startup bases. Hurt delayed Join starts both children at .05 and finishes rotation at .30, preserving residual values on replacement. See source-tween-parity.md for evidence and boundary tests. Remaining differences are explicit: camera shake still uses a deterministic decaying sine, not DOTween's random trajectory. Camera shake is screen-plane offset, not full3D translation. Live event endpoints now capture actual animated 3D transforms once per phase through injectable samplers, with current-clock evaluation before model transitions. Legacy saves without optional visual geometry alone retain old model-target reconstruction. Transient hurt/shake are not serialized and do not replay on load. Optional private HitUI sprites, source rects and effectiveness art are composed by VisualAssets; missing metadata/media uses generated semantic text. Font rendering remains a native fallback, while source-equivalent punch mathematics is now covered by headless regression. GPU projection, sprite orientation and manual input acceptance remain unverified.

`test_combat_presentation.gd` tests phase reconstruction, midpoint jump, current-home return, source-duration linear flight, no snapshot mutation, deduplication, removal/merge cleanup, flash legs, miss behavior, replacement and reset. Existing feedback/equipment/board tests cover integration and external pause clocks. All tests are headless and make no visual-parity claim.
