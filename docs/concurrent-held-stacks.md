# 独立卡牌拖持的模型边界

依据锁定 Unity `a11a89b04cea8370476f2559b639bb9b4cbc08d8` 的
`CardController.OnPointerDown` / `OnPointerUp` 和
`CardInstance.TryAttachToNearbyStack`。原版拖持标记与暂停配方的原牌堆引用
归各自的卡牌，而不是归一个全局触点。因此通过输入准入的不同卡牌可以并存。
同一张卡牌的触点捕获、是否重复执行点击、屏幕投影和战斗拖持属于棋盘输入，
不由模型注册表判断。

- 每个显式捕获的卡牌编号独立登记一次实体拖持，归还或终结只结算该卡牌所
  持的实体牌堆及其原配方。旧单指针模型调用继续按原有语义运行，且不能
  覆盖其它持有者。
- 下层根卡仍在原拖持堆时，可以再从其后的一张卡分割尾部。两个登记指向
  分割后的两个物理牌堆；释放时原版允许把卡牌追加到另一仍拖持的堆。
  另一持有者保留原堆编号及所属卡牌。对应于已由某个拖持暂停的原始配方
  底堆的新拾取，或原持有根卡已经消失、无法确认分割边界的情况，暂不
  接受并发拾取，直到独立验证原调用及相互结算次序。这是保守限制，不是
  原作禁止该操作的结论。
- Godot 原生存档在隔离副本按准入顺序模拟所有当前堆的普通未附着释放，
  不保存临时拖持、触点或屏幕姿态，不改动游戏当前对象、配方暂停、随机
  状态或信号。此处不声明与 Unity 存档格式或并发恢复行为一致。正在同步
  改动任意一个持有堆时，存档仍拒绝捕获中间态。

`test_held_stack.gd` 覆盖两路配方暂停、逆序释放、原堆回挂资格、共同底堆上的
独立分割及回挂、模型旧入口与显式入口并存，以及双路隔离存档。模型测试
不替代棋盘真实输入、图形运行或实体多指验证。
